<h2>二、出口侧参数怎么读</h2>
<h3>归属类型要看到登记方</h3>
<p>只看「住宅」两个字不够，要看地址的登记方是谁。查 whois 时，登记方是本地运营商或宽带服务商，才算原生态；登记在云服务、托管商名下，即使宣称住宅也不算。养成期建议全部使用前者，因为新号没有历史行为支撑，对出口类型最敏感。</p>
<h3>复用率问清楚三件事</h3>
<p>这条线当前挂几个号、上一位使用者是什么类型、换手时是否冷却。三个问题服务商未必全答，但问与不问差别很大。独享的成本通常比共享高出三到五成，仅供参考，养成期这笔钱值得花在主力号上。</p>
<h3>在线时长与变更频率不是同一件事</h3>
<p>在线时长讲的是不断线，变更频率讲的是地址本身换不换。有的线路不断线但每次重连换地址，表面稳定实际最伤。养成期应选「长在线加地址固定」，即静态住宅，代价是灵活性差一些。</p>
<h2>三、环境侧参数怎么读</h2>
<h3>一个号一套环境的三个硬指标</h3>
<p>配置文件独立、时区与出口地区对齐、浏览器大版本锁定。前两项决定会不会串，第三项决定会不会漂。三者齐了，环境层基本不会出问题。</p>

<h3>并发与时段的隐藏参数</h3>
<p>同一个号并发超过三路，容易在日志里留下整齐的并发记录。养成期建议单号并发一路，把任务排成队列。时段上尽量避开当地凌晨两到五点，那个时段的正常家庭流量本来就少，集中请求更显眼。</p>
<h2>四、计费与调度参数</h2>
<p>计费粒度直接决定试错成本。按小时计费适合先跑七天看稳定性，包月适合已经验证过的号。混合用法是先用小时计费试三条，稳定后转包月，能省下不少无效支出。</p>

<h3>调度参数：别让系统自己换线</h3>
<p>很多客户端默认开启「自动切换最快节点」，这条对养成期是灾难。自动切换会在无感知的情况下换掉出口，日志里看不出原因。建议关掉自动切换，改成手动白名单，只允许指定线路。</p>
<h2>五、参数组合的三套模板</h2>
<h3>模板甲：单号试水</h3>
<p>一条独享静态住宅、按小时计费、单环境单并发、连续观察七天。适合刚拿到号的前一周，成本最低，读数最干净。</p>
<h3>模板乙：主力养成</h3>
<p>一条独享静态住宅包月、地址固定、环境独立、并发一路、每日固定时段使用。适合已经过了首周验证、准备长期用的号。</p>
<h3>模板丙：多号并行</h3>
<p>每号一条独立出口，环境按号编号，调度走白名单，日志按号分文件。这一套管理成本高，但出问题能立刻定位到具体账号，规模上去以后反而省心。</p>
<h2>常见问答</h2>
<h3>参数表里最该优先确认哪一项？</h3>
<p>答：归属类型的登记方。这一项不对，后面所有参数调优都是白费力气，因为出口性质从根本上不匹配。</p>
<h3>养成期一定要用静态住宅吗？</h3>
<p>答：建议是。动态地址在换 IP 时容易触发重新确认，新号本来就没有信任积累，多一次确认就多一分风险。</p>
<h3>延迟高会不会影响稳定性？</h3>
<p>答：延迟影响的是超时与重试，不直接决定通过率。把脚本超时从默认值放宽到 p95 的两倍，比换一条低延迟的机房线更有用。</p>
<h3>参数都对了还是被要求验证怎么办？</h3>
<p>答：先看是不是环境漂移或行为节奏问题，再看是否与其他号共用了同一时段。参数只能消除结构性风险，不能消除行为层面的异常。</p>
